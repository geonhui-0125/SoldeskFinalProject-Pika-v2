# 화면설계 기준과 Figma 작업 기록

- 기록일: 2026-11-11
- 목적: 대화·Codex 작업 기록에만 남았던 화면설계 방향과 실제 Figma 산출물의 위치를 저장소에서 찾을 수 있게 한다.
- 현재 파일명: `PIKA_v1`. 앞선 작업 기록의 `PIKA_v2`는 같은 연결 파일의 이전 표시명이다. 플러그인이 파일 키를 반환하지 않아 직접 링크는 기록하지 않는다.
- 현재 페이지·프레임·컴포넌트 ID: [Figma 인벤토리](design/figma-inventory.json). 이 파일은 위치 색인이며 원본 디자인 백업은 아니다.

## 1. 합의한 디자인 방향

프론트엔드나 독자적인 디자인이 프로젝트의 중심은 아니다. V1의 실제 PC 화면을 고충실도로 옮긴 레거시를 기준으로, 레이아웃·색상·상품 카드·기본 폼을 이어가고 미완성·어색한 화면과 v2에서 달라지는 업무 흐름을 개선한다. 초기 회색조 시안을 최종 디자인 기준으로 삼지 않는다.

인증과 사용자 정보 관리는 분리한다. 로그인·로그아웃·가입·비밀번호 재설정은 인증 영역이고, 로그인한 회원의 정보 수정·비밀번호 변경·탈퇴는 **마이페이지의 서브페이지**다. 마이페이지 본문과 하위 화면은 같은 사이드 메뉴와 공통 셸을 사용한다. 인증 화면에는 마이페이지 메뉴를 넣지 않지만 헤더·플로팅 UI·공통 오버레이는 공유한다.

PC 기준은 1440×1000이다. 이는 뷰포트 기준이며 긴 목록·본문의 구현 높이를 고정한다는 뜻은 아니다. 모바일·최소 지원 폭은 아직 별도 결정이 필요하다. 화면과 업무 상태를 검토한 뒤 API 명세를 작성한다.

07은 원본 화면 55개를 상품 탐색·계정·상품 관리·마이페이지·거래와 리뷰·채팅과 알림·관리자의 7개 섹션으로 구분한 포트폴리오 자료다. 초기 60개 복제 중 사용자가 테스트 페이지로 지정한 5개를 제거했다. 전체 흐름 안내와 실제 화면 썸네일 동선, 같은 섹션의 대표 화면 사이 행동 화살표를 함께 사용한다. 섹션 간 긴 연결선을 모든 화면에 펼치기보다 안내도에서 대표 흐름을 읽고 원본 화면으로 이동하는 구성이다. 임의의 테스트 화면을 다시 복원하지 않는다.

08에는 현재 섹션 직속 또는 페이지 직속 프레임 120개가 조회된다. 안내판·오버레이·예외 상태를 포함한 위치 색인 수로, 기능 120개 또는 설계 완료율을 뜻하지 않는다. 03에는 컴포넌트 53개가 조회되며 중첩 원본도 포함한다.

헤더 높이는 V1 측정값 **150px**, 햄버거는 **30px, 헤더 내부 y=103**을 기준으로 복원했다. 계정·서비스 메뉴는 공백을 넣은 한 문자열 대신 개별 항목과 Auto Layout을 사용한다. 원본 아이콘·검색창·메뉴 배치를 바꾸면 클릭 영역과 팝업 기준 위치도 다시 측정한다.

컴포넌트 원본에 다른 페이지의 프로토타입 목적지를 직접 연결하지 않는다. 공통 원본은 03에 두고 화면 이동·오버레이 연결은 08의 화면 단위 클릭 영역에서 관리한다. 인스턴스를 분리하거나 화면별 공통 UI를 다시 그리지 않는다. 자세한 반복 작업 규칙은 저장소 [AGENTS.md](../AGENTS.md)에 둔다.

## 4. 실제 진행한 설계와 확인 범위

### 인증·마이페이지

인증과 마이페이지 회원정보 섹션을 분리했다. 마이페이지·하위 화면 12개에 공통 셸과 사이드 메뉴를 적용하고, 인증에 실패·입력 오류·처리·완료·링크 만료 등의 변형을 추가했다. 이전 작업에서 수정 화면 24개의 공통 원본 참조와 렌더를 확인했다. 인증 입력 22개와 버튼 12개를 공통 인스턴스로 전환한 기록이 있다. 이 수치는 당시 검사 범위이지 현재 전체 상태의 완전 검증 수가 아니다.

Present에서 `V2 PC · 인증`, `V2 PC · 마이페이지 / 회원정보`, `V2 PC · 이메일 재설정 링크 진입`으로 진입한다. 상세 오류 변형도 별도 시작점이 있다. 정보 편집·서버 검증·세션 만료의 모든 경우가 완성된 것은 아니다.

### 관리자

`16:2252` 섹션에 본문 상태 31개와 확인 오버레이 8개, 안내판 2개를 구성했다. 회원 경고·제한·해제, 상품 숨김·복구, 신고 기각·조치, 주문·결제 재조회, 환불 처리 중·결과 미확정·실패·완료, 감사 기록, 실패 작업 복구, 권한·조회 오류 등을 시연한다.

본문 31개의 공통 헤더 원본 참조와 대표 전이 13개를 확인한 작업 기록이 있다. Present 시작점은 `V2 관리자 · 운영 홈`, `회원 제한·해제`, `신고 검토·숨김`, `거래·환불`, `실패 작업 복구`다. 화면의 기간·건수·사유·주문은 예시이며 실제 제재·환불 API가 작동하지 않는다. 조사의 P0/P1 후보 전체가 확정되었다는 뜻도 아니다.

### 리뷰

공개 상세·작성자 수정과 삭제·조회 실패 복구 등 18개 상태를 반영했다. 원본·화면 ID, 변경 내용, 기능별 잔여 작업은 [마감 점검](design-completion-audit.md)에 기록했다. 신규 리뷰 작성 화면은 별도 보완 대상이다.

## 5. 복구·인수인계 절차

1. Figwright `ping`으로 연결 파일과 페이지를 확인하고 `get_pages`로 현재 이름·시작점을 읽는다. 파일명만으로 다른 파일이라 판단하지 않는다.
2. 인벤토리의 ID로 대상과 03 원본을 조회한다. ID가 바뀌면 현재 노드에서 확인한 뒤 색인을 갱신한다.
3. 관련 화면·원본·기능명세를 읽고 수정한다. 공통 변경은 방문자·회원·마이페이지·관리자 대표 화면까지 확인한다.
4. 원본 참조·가시성·클릭 영역·프로토타입 목적지를 구조 검사하고 렌더로 확인한다. 대량 조회는 작은 묶음으로 나눠 결과를 확인한다.
5. 작업 후 인벤토리·설계 기록·잔여 작업표를 갱신한다. 프레임 존재, 클릭 연결, 실제 서비스 구현을 구분해 보고한다.

Figma 편집 원본은 Figma에 있다. 이 저장소의 기록과 JSON만으로 원본 그래픽을 복원할 수 없으며, `.fig` 내보내기·시점별 디자인 백업은 아직 확보하지 않았다. 플러그인이 연결되어야 실제 노드와 화면을 재검증할 수 있다.
