# V1 로컬 구동·자료 이관 기록

- 정리일: 2026-11-11
- 성격: v2 설계에 사용한 V1 로컬 실행의 과거 작업 기록. 이번에 서버를 다시 구동하거나 데이터를 재계수한 결과가 아니다.

## 과거에 확인한 내용

JDK 17 설치와 Gradle Wrapper 8.14.3의 `compileJava` 성공을 확인했다. Docker Oracle XE 21c 컨테이너 `pika-oracle`, 볼륨 `pika-oracle-data`, 전용 개발 스키마를 준비했다. 초기 SQL의 삭제 구문을 제외하고 `PRODUCTS`를 `MESSAGES`보다 먼저 생성하도록 순서를 조정해 테이블·시퀀스·카테고리 22개를 적재했다.

V1 앱은 당시 8080 포트 충돌로 8081을 사용했다. Playwright에서 홈·로그인·가입·검색의 HTTP 200과 페이지 오류 없음을 확인하고, 비로그인 상태에서 상품 등록·마이페이지·채팅 진입이 로그인으로 이동하는 것을 확인했다. 이는 전 경로 권한 검증이나 v2 수락 테스트가 아니다.

사용자 제공 `datasetAdd (카테고리 수정본).txt`와 `mock.zip`을 정제해 상품 942건·리뷰 5건, 참조 테스트 계정, 상품 이미지 2,404개를 준비한 기록이 있다. 이미지 경로는 사용자 홈의 `pika_uploads/products`였다. 당시 홈의 상품 카드 20개와 화면 이미지 23개가 정상 로딩됨을 확인했다. 데이터 개수는 과거 목업 적재 시점의 값이며 현재 DB의 보장값이 아니다.

이후 V1 실제 브라우저 캡처와 편집용 Figma 복제에 사용했다. 파일·페이지와 최종 디자인 기준은 [화면설계 기록](design-record.md)을 따른다. 로컬 계정 비밀번호·API 키·설정 원문은 문서와 저장소에 옮기지 않는다.

## 로컬 산출물의 보존 범위

과거 세션에는 `/tmp/pika-schema.sql`, `/tmp/pika-mock-dataset.sql`, `/tmp/pika-v1-capture`, `/tmp/pika-v1-layers` 등 임시 SQL·캡처·분해/이관 스크립트 경로가 남아 있다. 이번 점검 시 해당 작업물은 `/tmp`에서 확인되지 않았다. 세션에 경로가 있다는 이유로 재현 가능한 저장소 스크립트라고 간주하지 않는다.

원본 SQL·목업 ZIP과 소스는 저장소에 남아 있고, 실행 유의점은 [README](../README.md#5-로컬-실행)에 있다. 그러나 정제·캡처 과정을 그대로 재실행하는 도구 묶음은 아직 버전 관리되지 않는다. 임시 스크립트의 복구·v2 사용은 별도 검토 후 수행하고, v2 반복 실행은 새 스키마의 [시딩 계획](delivery-and-test-plan.md)에 맞춰 작성한다. 원본 Figma 그래픽의 별도 백업도 아직 확보하지 않았다.

sudo가 필요한 재구동·설치 작업은 반드시 사용자 tmux에서 실행한다. 이 문서화 작업에서는 sudo나 DB 초기화를 실행하지 않았다.
