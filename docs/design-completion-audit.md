마이페이지 활동 `12:1230`에는 내 리뷰 항목을 넣어 작성자 상세로 연결했다. 상품 하단 `12:936`, `12:1760`의 리뷰 보기에서도 판매자 후기 목록으로 진입한다.

공통 헤더·햄버거·플로팅 UI·입력·버튼은 보일러플레이트 인스턴스를 사용했다. 후기 카드, 거래 상품 요약, 별점, 로딩 골격, 삭제 확인도 `03`에 공통 원본으로 등록했다. 별 아이콘은 V1이 쓰던 Font Awesome 6.7.2의 실제 SVG를 사용했다([원본](https://github.com/FortAwesome/Font-Awesome/blob/6.7.2/svgs/solid/star.svg), [라이선스](https://github.com/FortAwesome/Font-Awesome/blob/6.7.2/LICENSE.txt)).

Present 시작점은 `V2 리뷰 · 공개 후기`, `V2 리뷰 · 내 후기 수정·삭제`, `V2 리뷰 · 조회 실패 복구`다. 수정→저장 중→수정 완료, 삭제 확인→삭제 완료, 조회 재시도→로딩→상세의 연결을 확인했다. 화면은 고정 예시 데이터이며 별점 입력·텍스트 입력·평점 재집계·서버 권한 검증을 실행하지 않는다. 삭제 실패 등 일부 예외는 검토용 독립 화면이다.

## 마감 전에 결정할 정책

1. 배송비, 결제·승인 대기 만료, 배송 지연, 자동 구매 확정, 운송장 정정·재배송 범위.
2. 부분 환불·반품·분쟁의 포함/보류, 환불 후 리뷰·평점 표시. 발송 이후 처리를 관리자에게 연결하는 사용자 접수 경로.
3. 탈퇴·이용 제한 중 진행 거래의 이행과 개인정보 보관·익명화.
4. 채팅 차단·신고·첨부 보관 및 접근 범위, AI 대화 보관·취소·근거 부족 처리.
5. PC 최소 폭과 가로 넘침 규칙. 현재 기준은 1440px이며 모바일 화면을 이번 범위에 자동 추가하지 않는다.

미결정 항목은 확정된 것처럼 문구나 버튼을 만들지 않고, 결정 항목·설계 가정·보류 기능을 구분한다.

## 화면설계 마감을 위한 절차

1. **범위표 확정:** 기본·확정·정책 검토·후속 기능을 구분하고 위 정책을 결정하거나 해당 기능을 명시적으로 보류한다.
2. **화면 상태표 작성:** 기능 ID마다 화면 ID, 경로, 진입 주체, 권한, 표시 데이터, 입력 검증, 가능한 명령, 다음 화면을 연결한다. 정상·빈 값·로딩·실패·권한 없음·충돌 중 적용되는 상태를 기록한다.
3. **거래 핵심 경로 완성:** 상품→주문/배송지→결제→승인→운송장→구매 확정→리뷰 작성, 취소·관리자 처리 경로를 먼저 닫는다.
4. **남은 영역 보완:** 상품·검색→채팅/AI/알림→회원정보·리뷰 작성 순서로 기존 V1 화면을 공통 원본에 맞추고 예외·복구 동선을 추가한다.
5. **보일러플레이트 검사:** 새 화면과 공통 변경 때마다 원본 참조·분리 인스턴스·중복 원본을 확인한다. 헤더 150px, 실제 햄버거·검색 아이콘, 클릭 영역과 오버레이 위치, 마이페이지 사이드바를 렌더와 노드 트리 양쪽에서 검증한다. 입력 라벨·오류 안내·포커스·대비도 함께 점검한다.
6. **프로토타입 통합 검토:** 방문자 탐색, 구매자 거래, 판매자 이행, 내 정보, 메시징/AI, 관리자 처리의 대표 경로를 이어 본다. 같은 예시 주문·회원·상품을 사용하고 뒤로·취소·재시도·만료·새로고침 이후 복구를 확인한다. 독립 예외 화면과 실제 연결 경로를 구분한다.
7. **사용자 검수·버전 고정:** 정상 경로와 위험도가 높은 예외부터 실제 Present로 검토하고 승인/재작업 기록을 남긴다. 합의된 화면을 기준 버전으로 고정한다.
8. **API·구현 계약 작성:** 화면 상태표를 HTTP/WebSocket/gRPC 명세, 페이지·오류·상태 전이·검증 규칙, React MVVM 책임으로 옮긴다. Oracle 원본과 MongoDB·검색 반영 시차가 화면에 어떻게 보이는지도 정의한다. 디자인 변경 시 명세를 같이 갱신한다.

마감 기준은 화면 수가 아니라 **첫 범위의 기능마다 적용되는 상태·권한·동선이 설명되고, 공통 UI를 참조하며, 주요 경로가 시연되고, 미결정 정책이 해소되거나 보류로 표시되고, 사용자 검수를 통과한 상태**다.

## 확인 범위와 한계

페이지의 프레임 목록, 대표 화면의 실제 레이어·공통 컴포넌트 참조, 기능·거래 명세를 대조했다. 리뷰 상세·수정의 렌더와 삭제 확인 오버레이를 확인했고 주요 프로토타입 반응을 조회했다. 전체 화면 모든 좌표·모든 클릭의 완전 탐색이나 실제 API·접근 제어·데이터 영속성·동시성 테스트를 수행한 기록은 아니다. 기존 V1 화면의 존재만으로 v2 요구사항이 충족되었다고 판정하지 않았다.
